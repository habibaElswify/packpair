## Rubric mapping

### UW Community Impact (10 pts)

PackPair solves a recurring UW pain point: teacher- and student-driven team formation in courses with project components. Instead of self-selecting groups (which excludes new students, repeats friend cliques, and silos skills), the instructor pastes a Canvas Gradebook CSV and the AI forms balanced teams.

- UW Google sign-in gate enforces `@uw.edu` server-side (`web/lib/supabase/server.ts`, `web/app/auth/callback/route.ts`).
- Canvas API verification — only users with a real Teacher/TA enrollment can create events (`web/lib/canvas.ts`, `web/app/instructor/verify.tsx`).
- Roster-gated joins — when an instructor imports a roster, only those emails can join with the code (`web/app/actions.ts:joinEvent`).
- UW brand colours: `#4b2e83` purple, `#ffc83d` gold, used consistently across every surface.

### AI Integration (15 pts) — three central techniques

1. **Constraint-satisfaction (search)** — Google OR-Tools **CP-SAT** integer program in `solver/cpsat_matcher.py`. Enumerates `C(n,k)` candidate teams, weighted objective: `10 * |skills_union| + 5 * |shared_availability| + 3 * |shared_topics| + 5 if comm_styles ≤ 2`. Greedy fallback in `solver/matcher.py:_greedy` for rosters >40 students (CP-SAT OOMs Render free tier at ~75). **A/B comparison on the landing page**: on the same 18-student problem CP-SAT delivers +39% objective uplift over greedy.

2. **Bayesian peer reputation** — `solver/reputation.py`. Beta(α,β) posteriors per dimension (participation, communication, technical). Conjugate update from 1–5 ratings: `s = (stars-1)/4 → α += s, β += 1-s`. Cold-start mitigation via neutral `Beta(1,1)` prior. `team_bonus` is **confidence-weighted** — each student's composite is shrunk toward 0.5 by `smoothing / (smoothing + n_observations)` so a single rating can't swing the objective. Tested in `tests/test_reputation.py`.

3. **k-anonymity privacy guard** — `solver/privacy.py`. Public reputation suppressed until ≥5 ratings back it. Prevents re-identification of small-team raters and disincentivises gaming. UI surfaces "need 5 ratings to disclose (have N)" — honest about the threshold rather than hand-waving.

**Hyperparameter justification table** in `README.md` documents every weight (10, 5, 3, 5, 20, 4, 5) with rationale.

### Technical Execution (25 pts)

**Three-tier deployment, all live, all free-tier:**

```
Next.js 16 (Vercel)  ←→  Supabase (Postgres + Auth + Realtime + RLS)
        ↕
FastAPI solver microservice (Render)
        ↕
OR-Tools CP-SAT + Bayesian reputation + k-anonymity
```

- **Database**: 5 versioned migrations (`supabase/migrations/0001`–`0005`), row-level security enforced, not bolted-on. Cross-event reputation recompute (`web/app/actions.ts:rebuildReputationForEvent`).
- **Auth**: Google OAuth via Supabase, `@uw.edu` server-side, `proxy.ts` (Next.js 16's renamed middleware), three role flags (`is_instructor`, `is_app_admin`, owner-of-event).
- **CI**: `.github/workflows/ci.yml` runs `pytest tests/` and `npm run build` on every push.
- **Tests**: 39 Python tests across `tests/test_matcher.py`, `tests/test_api.py`, `tests/test_stress.py`, `tests/test_reputation.py`. All green.
- **Stress-tested**: every student placed across rosters of 9, 18, 30, 60, 120 (`docs/benchmarks.json`).
- **Edge cases handled**: missing profiles (straggler policy), >40 students (greedy fast-path), cold-start solver (4s timeout + UI hint), duplicate roster emails (unique constraint), late drops (`reformAffectedTeams` re-solves only affected teams), instructor accidentally hits "Simulate ratings" on real data (gated behind `is_app_admin`).

## How AI is *meaningfully embedded* (not a side-chat)

| Surface | AI mechanism | Code |
|---|---|---|
| Event page → "Form teams" | CP-SAT integer program over weighted objective | `solver/cpsat_matcher.py:solve` |
| Team card → "Why this team" | Solver returns structured `TeamRationale` | `api/main.py:TeamRationale` |
| Rate teammates | Bayesian Beta update on submit | `web/app/actions.ts:saveRatings → rebuildReputationForEvent` |
| Reputation page | Cross-event Beta posteriors + 95% CI bars | `web/app/events/[id]/reputation/page.tsx` |
| Public composite | k-anonymity guard (k=5) | `solver/privacy.py:RollingAggregator` |
| Pre-flight | Anomaly detection on the roster | `web/app/actions.ts:rosterPreflight` |
| Re-form affected teams | Scoped CP-SAT re-solve preserving stable teams | `web/app/actions.ts:reformAffectedTeams` |

There is no chat. AI is the application loop.

## Tech stack

| Layer | Technology | Why |
|---|---|---|
| Frontend | Next.js 16 (App Router, TypeScript) | Server components for free SSR + Server Actions for typed RPC |
| Auth | Supabase Auth + Google OAuth | UW Google = SSO every UW student already has |
| Database | Supabase Postgres + Row-Level Security | RLS enforces "students see only their event" at the DB level, not just app code |
| Realtime | Supabase Realtime | Live updates when teams form, no polling |
| Backend AI | FastAPI + Pydantic | Thin typed layer over `solver/` package |
| Solver | Google OR-Tools CP-SAT + greedy fallback | Exact solve for small classes, polynomial for large |
| Reputation | NumPy + scipy.stats.beta | Conjugate Beta updates + 95% credible intervals |
| Deployment | Vercel (web) + Render (solver) + Supabase (DB) | Free tier across the stack; zero credit cards used |
| CI | GitHub Actions | pytest + Next.js build on every push |

## User guide

### For an instructor
1. Sign in at `packpair.vercel.app` with your `@uw.edu` Google account.
2. Go to `/instructor`, paste a Canvas access token to verify your Teacher/TA enrollment.
3. Create an event (course label, target team size, remainder policy).
4. Import the roster — paste your Canvas Gradebook CSV (it parses the `SIS Login ID` column for NetIDs) or add students individually with the "+ Add student" form.
5. Share the join code with the class.
6. Once students fill profiles, the pre-flight check flags any anomalies (no profile, no availability, no skills, comm-style outlier).
7. Click "Form teams" — CP-SAT solves and persists.
8. After project ends, click "Open peer review" and share the rate-teammates link.
9. Export teams + outcomes as CSV for end-of-quarter records.

### For a student
1. Sign in at `packpair.vercel.app` with your `@uw.edu` Google account.
2. Click "Join with code" and enter the code your instructor gave you.
3. Fill your profile — at least 2 skills, 2 time slots, 1 topic. The save button stays disabled until each minimum is met.
4. Wait for the instructor to form teams; the page updates live via Supabase Realtime.
5. After the project, rate your teammates anonymously on 3 dimensions.
